# Research-Auto 기능 경계 정리 설계

## 목적과 범위

사용자가 승인한 방향은 수요 탐색 엔진, 고객 납품 기능, 실험 코드, 검증 자료 및 산출물을 구별하고 기능별로 커밋하는 것이다. 이번 정리는 동작 변경이나 새로운 상품 개발을 포함하지 않는다. 실험 결과를 공식 기회로 승격하지 않는다. 기존 CLI, import, 입력 제한, 검수 요구, 출력 구조를 유지한다.

## 접근 비교

- 전면 이동: `src/engine/` 아래로 기존 엔진을 모두 옮기면 물리적 분리는 좋지만, 다수의 오래된 import·문서·해시 결합 실행의 재현성을 위험하게 한다. 현재는 선택하지 않는다.
- 문서만 정리: 가장 안전하지만 재사용할 납품 코드가 여전히 최상위에 흩어지고 Excel→PDF 실행 코드가 결과물 폴더에 남는다. 목표를 충분히 만족하지 않는다.
- **선택: 점진적 물리 분리.** 새 `src/services/`와 `experiments/`를 만들고, 기존 공개 경로는 호환 진입점으로 유지한다. 동결된 엔진/검증 코드와 자료의 경로·내용은 그대로 둔다. 현재 엔진 패키지 경계를 문서로 명시하고, 향후 엔진 자체의 디렉터리 이동은 기존 증거·경로·해시를 별도 버전으로 검증한 뒤 진행한다.

## 이번에 확정할 구조

| 역할 | 정리 후 경로 |
| --- | --- |
| 엔진 및 현재 엔진 관련 실험 호환 경로 | `src/contracts/`, `src/source_spike/`, `src/extraction/`, `src/research_console.py`, `src/evidence_pilot_cli.py` (동결 유지) |
| 납품용 파일 정리 | `src/services/spreadsheet.py` |
| 납품용 기간별 보고서 | `src/services/periodic_report.py` |
| 납품용 송장/입금 대조 | `src/services/invoice_reconciliation.py` |
| 납품용 스캔 PDF 주문 작업 | `src/services/scanned_pdf/order.py`, 주문 화면 HTML. OCR/숫자 검증 유틸리티와 동결된 스캔 연구 코드는 기존 위치 유지 |
| 신규 Excel→PDF 가상 자료 실험 | `experiments/excel_pdf/` (변환 프로그램 판매용이 아님) |
| 결과물 | 기존 `artifacts/`, `outputs/`, `generated_images/` 그대로 보존. 앞으로 실험 코드를 새로 저장하지 않는 디렉터리 |

기존 서비스의 Python import와 `python3 -m ...` 명령(해당 명령이 기존에 있었던 경우)은 얇은 호환 파일로 계속 동작한다. 이중 구현은 금지한다. 스캔 PDF의 `HERE` 상대 리소스 및 OCR 경로를 명시적으로 보존한다. 이전 Excel→PDF 경로를 사용하는 문서는 새 실행 위치와 예전 기록을 구분해 갱신한다. 측정 결과와 원본 XLSX/PDF는 건드리지 않는다.

## 제약과 성공 조건

- 기존 엔진/수집기의 소스 바이트, 고정 프롬프트·스키마·골드·측정 결과 변경 없음. 새 모델 호출 및 외부 네트워크 수집 없음.
- 기존 사용자 미커밋 파일 보존. 전체 `git add .`, 강제 삭제, Git push 금지. `.git`이 읽기 전용이면 직접 커밋 시도 없이 정확한 대상 및 명령을 제공.
- 서비스 구현은 수요 탐색 엔진을 import하지 않는다. 기존 정기 보고서가 스프레드시트 정리를 재사용하는 관계 유지. 스캔 서비스에 한해 기존 숫자 검증 및 OCR 유틸리티 의존 허용.
- 자동 테스트에서 기존/새 import가 동일 객체이며 기존/새 CLI 도움말·합성 결과가 같음을 확인. 기존 서비스 회귀(스프레드시트, 보고서, 송장, 스캔 주문) 통과 및 XLSX 의존 테스트 별도 실행. 권한 내에서 전체 테스트를 실행하고 skip 이유 보고.
- 기존 엔진 실험의 미커밋 코드는 테스트 및 설정과 함께 기능별 커밋 후보로 명시하되, 공개 가능 여부가 확인되지 않은 근거 자료와 507MB 규모 스캔 실험 자료는 일괄 커밋하지 않는다. 민감한 로컬 자료에 의존하는 실행의 Git 단독 재현성 한계를 명시한다.
