# Scanned PDF / 행·열 레이블-숫자 연결 검증 실험 설계

상태: 사용자 검토용 설계 초안 (2026-11-22 KST), 독립 설계 검토 반영

## 1. 목적과 의사결정

사업 기회 후보는 일반 PDF 변환기가 아니라 **이미 생성된 Excel/CSV와 스캔 PDF 원본 사이의 값 및 행·열 의미 연결 오류를 찾아 검토 시간을 줄이는 도구**다. [구매자 조사](../../../artifacts/evidence-pilot/pdf-table-buyer-validation-20261122.md)에서 원본 대조 작업에 예산을 제시한 사례와 기존 제품의 스캔/레이블 제약을 확인했다. 유료 소프트웨어 수요 및 차별 우위는 아직 확정되지 않았다.

이번 사용자 승인 범위는 A 방식의 기술 검증 설계다. 20개 문서에서 오류 탐지 성능, 검토 시간, 기존 단순 검증 대안 대비 가치를 측정한다. 통과해도 사업 기회 자동 승격이나 서비스 개발·유료 고객 모집을 승인한 것은 아니다. 기존 [PRD](../../prd.md)의 근거/행동가능성 기준은 유지한다.

## 2. 고려한 방식

| 방식 | 장점 | 한계 | 결정 |
|---|---|---|---|
| A. 기존 OCR 기반 독립 원본 대조 + 제한된 오류 검증기 | 실제 차별 가설을 직접 검증, 기존 도구 결과를 입력으로 받음 | OCR 오류·행열 복잡도에 영향을 받음 | 사용자 선택 |
| B. OCR 엔진만 비교 | 원본 인식 병목을 확인 | 오류 탐지나 기존 스프레드시트 검증 가치를 측정하지 못함 | 보조 측정으로만 활용 |
| C. 완성형 서비스 개발 | 사용성·배포도 검증 가능 | 수요와 차별성이 불명확한 단계에서 과투자 | 이번 범위 제외 |

## 3. 범위와 제약

- 문서 20개: 이미지 기반 스캔 PDF(실제 공개/사용 허용 스캔 10개, 합성 스캔 10개를 우선 목표). 모든 문서는 표에 레이블과 숫자가 있으며, 개인정보·기밀·접근 제한 문서를 사용하지 않는다. 공개 문서 확보가 부족하면 실험 중 임의 교체하지 말고 부족을 보고하여 합성 대체 계획을 다시 승인받는다.
- 문서 단위로 단순 격자, 선 없는 표, 멀티라인/병합 레이블, 숫자/통화 표기, 스캔 품질 저하 등의 난이도를 분산한다. 여러 문서에 동일 템플릿을 반복해 독립 문서처럼 계산하지 않는다. 평가 범위는 문서당 사전에 지정된 표 하나, 1~2페이지, 8~20개 데이터 행과 3~6개 열(최대 120 데이터 셀)로 제한한다. 일부 표는 두 페이지에 이어지도록 구성한다. 원본 중 다른 표·페이지는 평가 대상에서 제외한다고 명시한다.
- 외부 고객 문서, 로그인·정책 우회, 유료 OCR/API 호출, 배포, 서비스 판매, 기존 Research-Auto 제품 파이프라인 변경은 비목표다. 로컬에서 실행하는 독립 실험을 우선하며, 필요한 OCR 의존성 선택은 구현 계획에서 실제 가용성을 확인 후 결정한다. 신규 외부 서비스/비용은 별도 승인.
- 정확성에 대한 보증, 무조건 자동 수정, 원본 대신 AI 추정값을 정답으로 취급하는 행위를 금지한다. OCR이 불확실하면 검토 대상으로 표시한다.

## 4. 실험 입력과 정답

각 문서의 원본 이미지, 출처/사용 허용 근거, SHA-256, 페이지, 문서 유형·난이도 및 정답 행/열/셀을 매니페스트에 고정한다. 공개 PDF는 사람이 원본을 대조해 정답을 검증하기 전에는 최종 평가에 포함하지 않는다. 합성 PDF는 렌더링 전 구조화 원본에서 정답을 만들고 이미지로 렌더링·스캔 변형하며, 정답과 평가 입력을 분리한다.

각 문서에는 두 개의 입력 버전을 둔다: 정상 스프레드시트와 오류 삽입 스프레드시트(총 40개 문서-입력 조합). 원본 PDF는 동일하고 오류 삽입은 스프레드시트에만 적용한다. 20개 오류 버전에 서로 겹치지 않는 오류를 각 3개씩, 총 60개 사전 기록한다. 아래 5개 유형을 각 12개 배정하되 동일한 셀이나 행이 다른 오류와 충돌하지 않도록 한다. 오류 배치 불가능 문서는 평가 전 배치를 조정하며 결과 확인 후 수정하지 않는다.

| 오류 유형 | 실험 정의 |
|---|---|
| 숫자 오인식 | 값 하나를 다른 숫자로 변경 |
| 행 연결 오류 | 두 행의 숫자 값 또는 값 묶음을 교환; 하나의 사건 |
| 열 연결 오류 | 같은 행의 서로 다른 의미 열 값을 교환; 하나의 사건 |
| 누락 | 명시한 셀 또는 행 하나 삭제; 하나의 사건 |
| 레이블 오류 | 숫자는 같지만 해당 행의 레이블을 잘못 변경/연결; 하나의 사건 |

합계가 그대로 유지되는 행/열 교환이나 레이블 변경을 반드시 포함한다. 단순 합계 검증만으로는 발견할 수 없는 오류여야 한다. 정상 입력은 오탐 평가용이며 20개 문서 수에는 중복 산입하지 않는다. 개발용 예시 데이터는 별도이고 20개 평가 문서나 정답은 검증기 튜닝에 사용하지 않는다. 매니페스트·비교 규칙·OCR 설정·오류 사건을 평가 전에 고정한다.

## 5. 비교군과 후보 검증기

세 방법에 동일한 원본 PDF와 입력 시트를 제공한다.

- 자동 비교군 B0: 기존 OCR 추출 결과를 활용한 숫자 형식·행수·합계 확인(수치가 없는 표는 해당 검사 불가로 표시). 행/열 의미 연결을 추론하지 않는다. 위치와 오류 유형을 특정할 수 있는 경고만 공통 사건 단위로 점수화한다. 합계 불일치나 단순 행수 차이처럼 특정 사건을 특정하지 못하는 경고는 일반 경고로 별도 보고한다. 후보 A에도 동일 기준을 적용한다.
- 후보 A: PDF 이미지를 독립적으로 OCR하고 해당 페이지의 토큰, 위치, 인식 불확실성을 보존. 시트의 행 레이블과 열 헤더를 원본 위치·문자·수치와 대조하여 잘못된 값, 행/열 연결, 누락을 찾는다. 동일 값 반복·모호한 레이블은 명확한 검증 결과가 아닌 검토 필요로 남긴다. OCR 엔진, 매칭 알고리즘 및 도구 구현 세부사항은 구현 계획에서 선택한다. A와 B0는 가능한 동일 OCR 출력을 사용해 비교 기능의 효과를 분리한다.
- 사람 비교군 H0: 도구의 자동 표시 없이 PDF와 시트를 직접 대조한다. H1: 후보 A가 표시한 항목을 같은 원본과 시트로 확인한다.

후보 A는 정답 파일과 오류 주입 목록을 읽지 않는다. 평가기는 제출된 오류 사건 위치·종류·원본 근거를 동결된 정답과 비교한다. 후보는 정상 셀을 임의 변경하지 않고 불일치/불확실성 근거를 제공한다. 출력 예: `page 2 / row: 상품 B / column: 금액 / 원본 위치 / 시트 값 / 불일치 이유 / 검토 필요 여부`. 입력이 이해 불가능해 전체 검토를 권하는 것만으로는 개별 오류를 발견했다고 계산하지 않는다.

## 6. 평가 및 성공 기준

- 평가 단위는 고정 오류 사건이다. 위치(문서·페이지·행/열 또는 정답이 지정한 누락 행/셀) 및 유형이 일치한 명시적 탐지를 TP로 계산한다. 중복 경고와 잘못된 위치/유형의 경고는 독립 TP가 아니며 사전에 고정한 일대일 매칭 규칙으로 FP 처리한다. 놓친 오류는 FN, 불확실/보류는 실제 오류에 대해 해당 사건을 특정하지 못하면 FN으로 계산한다. 불확실 경고량과 일반 검토 요청은 별도 보고한다.
- 정밀도 TP/(TP+FP) ≥95%, 발견율 TP/(TP+FN) ≥90%. 정상 입력의 FP 포함. 분모 0인 지표는 미평가(통과 아님). 전체 및 5개 유형별 결과, 문서 난이도 및 공개/합성별 성능, OCR 실패·불확실 표를 함께 제시한다. 유형별 성능 저하가 있더라도 전체 평균에 숨기지 않는다.
- 비교군 B0 대비 같은 오류 집합에서 행 연결·열 연결·레이블 3종의 TP 합계가 증가해야 하며, 각 유형의 TP가 B0보다 감소하면 통과하지 않는다. 추가 FP는 모두 보고하고 전체 정밀도 95% 기준을 적용한다. 실제 경쟁 제품 비교는 동일 파일·조건으로 직접 실행할 수 있는 경우에만 별도 명시한다. B0는 시장 제품 대리 지표일 뿐이며 경쟁 우위 증명으로 해석하지 않는다.
- 사람 검토 H0/H1: 20개 문서를 난이도·셀 수·오류 유형이 유사한 10쌍으로 미리 매칭한다. 8쌍은 오류 삽입 버전, 2쌍은 정상 버전으로 구성한다. 각 쌍에서 한 문서는 H0, 다른 문서는 H1로 무작위 배정하여 각 10개 문서, 총 20개 검토를 실시한다. 동일 리뷰어에게 동일 원본을 재제시하지 않는다. 두 그룹 모두 전체 평가 범위의 오류 위치/유형을 독립적으로 기록하고 최종 검토 완료 여부를 판단하는 동일 과제를 수행한다(실제 데이터 수정은 하지 않음). H1은 후보 경고를 참고하되 원본 전체를 확인할 수 있다. 정답은 숨기고 순서를 균형 배치한다. 쌍별 시간 단축률 `(H0 시간 - H1 시간)/H0 시간`의 중앙값 50% 이상을 잠정 목표로 한다. 그룹별 TP/FP/FN도 비교하며 H1의 FN 또는 FP가 H0보다 늘어나면 시간 절감만으로 통과하지 않는다. 작은 매칭 표본의 한계는 보고한다. 자동 평가를 먼저 실행하고 사람 검토 일정/참여자는 별도 확보한다. 검토자가 없으면 시간 지표는 PENDING이고 전체 성공 선언을 하지 않는다.
- 20개 문서는 탐색적 작은 표본이다. 모델·시장 전체에 일반화하지 않으며 원본 데이터 품질을 별도로 보고한다. 자동 탐지 지표와 실제 사람 검토 지표 및 제품/구매 검증은 독립 판단으로 기록한다.

## 7. 결과물과 착수 조건

실험 결과는 기존 Research-Auto와 분리된 로컬 결과 폴더에 재현 가능한 입력 매니페스트, 오류 주입 로그(평가에서만 접근), 후보/비교군 출력, 사건 매칭별 TP/FP/FN, 정량 비교표 및 사람 검토 시간 기록 양식으로 보관한다. 평가 결과를 보고서로 제공하고 기존 사업 기회 후보 보고서에 링크한다. 실제 사용자 구매 반응은 승인 없이 수집/접촉/결제하지 않는다.

성공 시 다음 단계는 독립 구매자 검증과 소규모 유료 파일럿 승인 요청이다. 실패 시 OCR 병목과 행/열 매칭 병목을 분리해 개선 실험 여부를 판단한다. 공식 사업 기회 상태는 기존 HOLD를 보존한다. 구현은 이 설계 승인 후 별도 계획을 작성하여 진행한다.
