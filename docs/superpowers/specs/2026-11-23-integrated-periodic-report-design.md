# 정기 실적 통합 보고서 설계

목적: 기존 검수 엔진에서 정상으로 분류됐지만 보고서 입력 규칙을 위반한 행이 최종 납품 XLSX의 정상 목록에 남는 문제를 해결한다. 가상 1,000행 실험의 확인 필요 150행과 정상 800행이 집계, 원본 기록, 검수 요약에서 일치해야 한다.

## 접근

- 기존 범용 `reconcile()`을 변경하면 이미 등록된 파일 정리 상품의 판단 기준까지 바뀐다. 제외.
- 보고서 생성 단계마다 별도로 검증하면 집계·내보내기 불일치가 재발한다. 제외.
- 선택: 기존 `reconcile()` 뒤에 보고서 전용 입력 검증을 한 번 수행하고, 보류된 행을 `exceptions`로 옮겨 최종 결과 객체 하나를 만든다. 집계와 기존 검수 내보내기가 이 객체만 읽는다. 별도 보고서 CLI를 제공한다.

## 제약 및 계약

- 기존 범용 정리 CLI의 결과와 의미를 유지. 외부 데이터 업로드·API·자동 예약·메일·서식 복원·수식 실행 없음.
- 동일 헤더 구조 CSV/XLSX 최대 3개/합계 1,000행/15열/개별 2MB. 키, 날짜, 분류, 수량 열은 서로 다른 기존 열이어야 한다.
- 날짜는 YYYY-MM-DD 텍스트, 수량은 0 이상 정수, 분류는 공백 제거 후 비어 있지 않아야 한다. 원본 값은 수정하지 않는다. 실패한 행에는 날짜/수량/분류 오류 사유를 남기고 집계에서 제외한다. 중복·키 충돌 처리 순서는 기존 엔진과 동일.
- 보고서 XLSX는 주간/월간 기간별 합계·건수·분류별 수량과 검수 요약·정리 결과·중복 목록·확인 필요·원본 행 및 파일 기록을 포함한다. 납품 파일은 검수 시점 스냅샷이며 원본 변경 시 새로 생성. 사람이 보류 건을 결정해야 한다.
- 수량 합계는 Excel 정밀도 내에서만 생성하고 범위를 초과하면 적격하지 않음으로 종료. 입력의 비정상/범위 초과는 명시적 거절 또는 보류, 가짜 0으로 대체하지 않는다.
- 공식 Research-Auto 증거 게이트나 가격/판매 등록은 변경하지 않는다. 실제 고객 데이터, 실제 판매 시간과 수익성은 별도 검증.

## 확인 기준

1,000행×3업무×2파일 형식×2주기에서 정상 800/중복 50/보류 150/미분류 0, 합계와 분류별 수치 독립 기대값 일치, 원본 좌표 1,000개 보존 및 XLSX 재열기 일치. 기존 전체 테스트 통과. 고객 파일에 제시된 보류 여부와 보고서 집계가 동일해야 한다.
