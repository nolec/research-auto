## Recommended next pilot

Use Companies House procurement-card CSV first, not another keyword search. Source preview has an occupational-equipment purchase category and a SaaS expenditure. No supplier identity needs to be collected. Supplier/vendor contact names, identifiers, transaction numbers, postcodes, tax IDs and raw files containing personal data are not stored. Preserve intentionally withheld values as withheld; never attempt identification. Scope to benign digital services and office operations. Pre-register date range, fixed file URLs, max file count and row cap, eligible expense categories and exclusions before opening a fresh corpus; inspect first eligible rows without selecting on model predictions. Keep signed/zero/refund amounts distinct, currency and payment date explicit, and distinguish per-row expenditure from aggregate and scheduled budgets. A procurement-card row cannot establish unmet need, loss, recurrence or buyer independence by itself. Prefer deterministic extraction of typed fields; V7 free-text prompt and previous TED reference contract do not certify arbitrary new structured data. Build a separately versioned adapter and fixture tests only after field semantics, licence, and collection limits are fixed. Compare source-backed positive payment rows with budget/award/zero-return counterexamples; independent gold precedes model inference. The two prior challenges and V7 run remain unchanged.
